The hardware this needs

An agent for every person needs chips that are cheap, and sip power.

Small local models fill the gaps of giant cloud models for the one person they serve at near-zero energy cost. Explore commodity local inference today vs. emerging analog and optical silicon.

Available today · Commodity Local Inference

Small open models on your own device

Compressed open-weight models already run on ordinary laptops and phones: full features with 16 GB of unified memory, or a quantized 4-bit mode with 8 GB (llama.cpp / GGUF).

  • Small open models on your own device Compressed open models already run on ordinary computers: full features with 16 GB of memory, a reduced mode with 8 GB.
  • Device keys and sealed computing Keys born from tiny manufacturing differences in each chip, and sealed areas of the processor, so a device can prove which agent ran on it.
  • Many small experts Only a few small specialist models switch on for each task, cutting energy roughly in proportion, and each device carries just the experts its owner needs.
  • Computing inside memory Analog chips do the maths where the numbers are stored, avoiding most of the energy spent moving data around.
  • Sensors that think Camera pixels that notice change themselves and wake the rest of the chip only when something happens.
  • Event cameras and spiking networks Vision that reacts in microseconds on a tiny power budget, because it only processes what changes.
  • Proof of what was computed Cryptographic proofs that an agent ran the model it claims, without revealing your data. Still too slow for large models.
  • Learning bound to one chip Learning that lives in the quirks of one analog chip cannot be copied out. A possible way for hardware itself to enforce an agent’s limits and lifespan. Speculative.
  • Weights wired into silicon A finished model built directly into a chip’s logic, running on microwatts. Only sensible once a model is stable enough to freeze.
  • Computing with light Thin optical layers that compute as light passes through them, before it ever reaches a sensor, at almost no power.

Always private, at every level: health, family, beliefs and life outside the role. Inner thoughts are never observed, and no one is ranked.

Visibility is a condition of accepting a role, taken on openly, never a penalty on ordinary people. Where exactly each line should fall is an open research question for us. The roles and reach are illustrations.

Not one giant mind

We think a single all-knowing AI is a fast way to take power from everyone at once. We work toward many specialized models instead, each trained for one person and answerable only to them.

Training without handing over your life

While large computers belong to a few companies, a personal model has to be trained on rented machines. We are designing for your data to sit in escrow during training, under keys that are destroyed when training ends, so the owner of the machine never keeps it. A design goal, not yet built.

Powerful roles first

As personal AI hardware gets cheap, we want the people who can most help or harm others to carry these agents first, so everyone else can ask where they stand. It is a path to unwinding concentrated power, so that advanced AI is not seized by a wealthy few, the future some call techno-feudalism.

OCap Sandbox & Runtime[Dennis & Van Horn, CACM 1966]

Object-Capability (OCap) Hardware-Isolated Sandbox

Formal definition: A security execution model where a process can access a memory region, file, or network socket if and only if it holds an unforgeable capability reference explicitly granted by the principal.

Inspect 4-step causal derivation (Intent → Mechanism)
1. Intent: Run personal agents over private medical & financial files with zero exfiltration risk. 2. Bottleneck: Ambient authority in POSIX/cloud containers lets prompt-injected agents pivot across the network. 3. Threshold: Deterministic WebAssembly OCap sandboxes with <1 ms capability table enforcement. 4. Mechanism: Every local tool executes with 0 ambient network handles; outbound facts require 3-of-6 local agent sign-off.
Transport Protocol[IETF RFC 9000 / RFC 9221]

IETF QUIC Multiplexed Streams & Unreliable Datagrams

Formal definition: A UDP-based, TLS 1.3-encrypted transport protocol supporting 0-RTT connection establishment, independent stream multiplexing without head-of-line blocking, and RFC 9221 datagrams.

Inspect 4-step causal derivation (Intent → Mechanism)
1. Intent: Coordinate agent-to-agent tasks peer-to-peer without centralized cloud SaaS relays. 2. Bottleneck: Legacy TCP/TLS handshakes incur 2–3 RTT latency and head-of-line blocking across NATs. 3. Threshold: ICE (RFC 8445) + 0-RTT QUIC stream binding per ephemeral capability token. 4. Mechanism: Each approved capability query opens a single-use QUIC stream that is cryptographically burned upon completion.
Verification Protocol[Necula, POPL 1997]

Proof-Carrying Code (PCC) & Deterministic Receipts

Formal definition: A binary or bytecode distribution protocol in which untrusted code carries an explicit machine-checkable safety and functional proof verified by the consumer before execution.

Inspect 4-step causal derivation (Intent → Mechanism)
1. Intent: Share working bug fixes and clinical workflows across agents without trusting unknown authors. 2. Bottleneck: AI code generation floods repositories with plausible-looking patches containing subtle vulnerabilities. 3. Threshold: Sub-second deterministic Wasm sandbox test-suite and invariant verification. 4. Mechanism: Ledger nodes only admit and route royalties to code bundles whose attached PCC receipt passes independent verification.
Royalty Attribution[Ghorbani & Zou, ICML 2019]

Monte Carlo Data Shapley Attribution

Formal definition: An equitable game-theoretic valuation φi(v) measuring each contributor’s marginal improvement to downstream task accuracy across permutation coalitions (Shapley, 1953).

Inspect 4-step causal derivation (Intent → Mechanism)
1. Intent: Pay independent coders, nurses, and technicians automatically when their know-how solves problems. 2. Bottleneck: Cloud AI labs scrape public repositories for free while platforms extract 30%–45% commissions. 3. Threshold: Truncated Monte Carlo permutation sampling over composable LoRA and PCC dependency DAGs. 4. Mechanism: Every verified task settlement distributes 95%+ of value directly to upstream contributors proportional to φi(v).
Federated Low-Rank Adapter (LoRA) Weight Merging[Yadav et al., NeurIPS 2023]

TIES-Merging & Low-Rank Adaptation (LoRA)

Formal definition: Parameter-efficient weight adaptation (ΔW = B·A, Hu et al., 2022) combined with Trim, Elect Sign, and Disjoint Merge (Yadav et al., 2023) to fuse specialist adapters without interference.

Inspect 4-step causal derivation (Intent → Mechanism)
1. Intent: Let local personal agents learn specialist skills privately and share compact weight improvements. 2. Bottleneck: Full-model fine-tuning requires data-center GPUs, and naive weight averaging destroys task accuracy. 3. Threshold: Top-20% magnitude pruning + sign consensus across rank-16 INT8 LoRA deltas (<18 MB). 4. Mechanism: Personal agents fine-tune LoRA adapters locally and merge peer-verified task deltas with zero raw data leakage.

Continuous Latent-Space Reasoning & Multi-Token Prediction

Cryptographic Co-Ops[Freedman et al., EUROCRYPT 2004]

Private Set Intersection (PSI) Buyer Coalitions

Formal definition: A multiparty cryptographic protocol allowing parties holding private sets Xi to compute only the intersection ∩ Xi (such as shared SKUs or CPT codes) without revealing non-intersecting items.
